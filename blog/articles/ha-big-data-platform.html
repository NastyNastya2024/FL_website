Как построить отказоустойчивую Big Data-платформу без простоя

Zero Downtime на «Дижитрек»: HA NameNode/YARN/Hive/Patroni, rolling restart с drain и health-check, guardrails SRE. Прод на 40 узлах и 1 ПБ+ без окна простоя.

Где данные в реальном времени (транзакции, биллинг, телеметрия), простой кластера — прямые потери. «Дижитрек» (Диджи Трек, DigiTrack) рассчитан на работу без окна. Масштаб — в «Как масштабировать Big Data-инфраструктуру от одного кластера до федеративной архитектуры».

HA критичных сервисов?

Краткий ответ: Ключевые варианты: HDFS: Active/Standby NameNode + JournalNodes, авто failover., YARN: ResourceManager HA., Hive Metastore: PostgreSQL Patroni, проверка через VIP., ZooKeeper: нечётный кворум, рестарт по одной машине..

  • HDFS: Active/Standby NameNode + JournalNodes, авто failover.
  • YARN: ResourceManager HA.
  • Hive Metastore: PostgreSQL Patroni, проверка через VIP.
  • ZooKeeper: нечётный кворум, рестарт по одной машине.

Rolling restart?

Краткий ответ: Patroni: reload без даунтайма или restart со switchover; VIP.

YARN NodeManager: drain → exclude, ждать numContainers=0, рестарт, RUNNING/healthy.

HDFS DataNode: dfs.exclude, IN_MAINTENANCE, рестарт, возврат в LiveNodes.

NameNode HA: сначала Standby, failover, затем бывший Active; кворум JournalNodes жив.

ZK + JN: по одной машине, проверка кворума после шага.

Hive Metastore: по инстансу, health-check БД через VIP.

JupyterHub: рестарт с проверкой до/после, минимальный impact.

Guardrails?

Не больше N узлов сразу. Таймауты: зависание шага останавливает волну. restart_matrix по фактическим изменениям. Pre/post: REST NameNode/RM, JMX, VIP PostgreSQL, порты Hive.

SRE: JMX, VIP, ZK quorum, порты — состояние кластера видно онлайн. Пром: 40 узлов, 1 ПБ+, регулярный rolling restart без окна для бизнеса.

Политика конфиденциальности

1. Общие положения

Настоящая политика обработки персональных данных составлена в соответствии с требованиями Федерального закона от 27.07.2006. №152-ФЗ «О персональных данных» и определяет порядок обработки персональных данных и меры по обеспечению безопасности персональных данных ООО "ДТ".

2. Цели обработки персональных данных

Персональные данные обрабатываются в следующих целях:

  • Обработка заявок и обращений пользователей
  • Предоставление информации о продуктах и услугах компании
  • Связь с пользователями по вопросам сотрудничества

3. Категории обрабатываемых персональных данных

Мы обрабатываем следующие категории персональных данных:

  • Фамилия, имя, отчество
  • Адрес электронной почты
  • Номер телефона
  • Информация, содержащаяся в сообщениях пользователей

4. Сроки обработки персональных данных

Персональные данные обрабатываются в течение срока, необходимого для достижения целей обработки, но не более 3 лет с момента последнего взаимодействия с пользователем.

5. Меры по обеспечению безопасности персональных данных

Мы принимаем необходимые правовые, организационные и технические меры для защиты персональных данных от неправомерного или случайного доступа к ним, уничтожения, изменения, блокирования, копирования, предоставления, распространения персональных данных, а также от иных неправомерных действий в отношении персональных данных.

6. Права субъекта персональных данных

Вы имеете право:

  • Получать информацию об обработке ваших персональных данных
  • Требовать уточнения, блокирования или уничтожения персональных данных
  • Отзывать согласие на обработку персональных данных
  • Обращаться с жалобами в уполномоченный орган по защите прав субъектов персональных данных

7. Контактная информация

По всем вопросам, связанным с обработкой персональных данных, вы можете обратиться по адресу: privacy@digitrack.com
